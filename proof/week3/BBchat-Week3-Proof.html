Summary

  • Chats are saved on the phone (BB-07): after a reload you stay signed in with your messages. Log out wipes them.
  • Installable and works offline (BB-08): BBchat can be added to the home screen and opens with no internet.
  • Proper title and link previews (BB-09): "BBchat by BENBAX" in the tab, and a branded preview card when the link is shared.
  • Fake dashboard removed (BB-10): the page with invented user numbers no longer exists.
  • Clean repository (BB-11): 15 old top-level files and folders removed (stubs, duplicates, dead configs); everything lives in app/.
  • One host: Vercel (BB-12): it publishes only the app, never the internal reports. GitHub now runs checks only.
  • About 2× faster, half the data (BB-13): first screen 1.92 s → 0.83 s and 272 KB → 144 KB on slow 4G, with the same look.
  • Correct documentation (BB-14): README rewritten; misleading files and the personal phone number removed.

1. Your chats are still there after closing the app BB-07

Test: sign in, send "Hello from Tema", then reload the page.

Risk if not fixed: Users lose everything when the page reloads or the phone closes the tab. Nobody can come back to the demo.

2. BBchat opens even with no internet BB-08

Test: open the app once, switch the network off, then reload.

3. BBchat can be installed on phones BB-08

The browser's own installability check, run on both versions, plus the new home-screen icons.

Before: "no-manifest". After: 0 errors, service worker running, opens offline.

Risk if not fixed: It can't be added to the home screen, and it shows a "no internet" error offline, which is a basic expectation for a chat app on mobile data.

4. Proper page title, description and link previews BB-09

Read from the live page in the browser. The preview card is what WhatsApp, Facebook, X and LinkedIn show when the link is shared.

Risk if not fixed: It looks unbranded and unprofessional, and shared links appear as bare text.

5. The fake dashboard is gone BB-10

Test: open /dashboard.html on each version.

Risk if not fixed: Invented figures ("1,247 users") on a public page mislead partners and investors and damage credibility.

6. Clean repository, one host, correct docs BB-11, BB-12, BB-14

Top-level files from git, before and after, and the hosting setup.

Risk if not fixed: BB-11: Developers edit files that do nothing, and dead copies bloat the site. BB-12: Pushing to main would have published the whole repository, including internal reports, to the public internet. BB-14: They mislead the next developer, and the old README exposed a personal phone number.

7. Faster and lighter, same look BB-13

Measured, not estimated: 3 cold loads per version on simulated slow 4G.

Risk if not fixed: A slow start on mobile data and about 2× the data cost; users may give up before the app opens.
